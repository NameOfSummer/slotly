# Slotly

自分の Google カレンダーの空き時間に、相手が **Google アカウントなし** で会議を予約できる [Google Apps Script](https://developers.google.com/apps-script) の Web アプリです。

1つのウェブアプリデプロイが、1つの予約ページです。Calendly のような「1つのURLの中に複数のイベントタイプ」はありません。所要時間と Meet の有無は、ゲストがそのページ上で選びます。

## できること

- ゲストは **お名前** と **メールアドレス** を入れて予約する（予定のタイトル・説明は任意）
- 所要時間は **15分刻み、15分〜240分（4時間）**
- 場所は **Google Meet / Meetなし**（ゲストが予約時に選ぶ）
- 空きはホストのカレンダー予定＋受付時間＋バッファから計算する
- 予約できるメールの **ドメインを制限**できる（空なら制限なし）
- 確定後、ゲストに確認メールを送り、Google カレンダー招待が届く。Outlook などには ICS ダウンロードを用意
- 確認メール（または確定画面）のリンクから **キャンセル** できる。キャンセルするとホスト側のカレンダー予定も削除される
- カレンダー予定の説明にはキャンセル URL を入れない（キャンセルはメールと画面のリンクだけ）

管理画面は予約一覧ではありません。受付時間やカレンダーの設定だけです。ページ右上の **使い方** から、ゲスト向け・管理向けの手順を見られます。

---

## 導入方法

GitHub からクローンし、自分の Google アカウントへデプロイします。相手に渡すのは **予約ページの URL だけ** です。管理画面の URL と管理キーは渡さないでください。

### 必要なもの

- [Git](https://git-scm.com/)
- [Node.js](https://nodejs.org/)（`clasp` と、任意のローカルプレビュー用）
- ホスト側の Google アカウント（カレンダーの読書きとメール送信の権限が必要です）

### 1. リポジトリをクローンする

```bash
git clone https://github.com/NameOfSummer/slotly.git
cd slotly
```

SSH を使う場合:

```bash
git clone git@github.com:NameOfSummer/slotly.git
cd slotly
```

`.clasp.json`（どの Apps Script プロジェクトに上げるか）はこのリポジトリに含まれていません。クローンしただけでは Google 上には何も作られません。次の手順で自分用のプロジェクトを作ります。

### 2. clasp でログインし、スクリプトを Google に上げる

```bash
npm i -g @google/clasp
clasp login
```

`clasp create` の前に、同じ Google アカウントで [Apps Script のユーザー設定](https://script.google.com/home/usersettings) を開き、**Google Apps Script API** をオンにします。オフのままだと `User has not enabled the Apps Script API` で止まります。オンにした直後は数分かかることがあるので、失敗したら少し待って再実行してください。

クローンしたフォルダで、スタンドアロンの Apps Script プロジェクトを作り、アップロードします。

```bash
clasp create --type standalone --title Slotly
clasp push
```

`clasp create` が `.clasp.json` を作ります。このファイルは Git に含めないでください（他人のプロジェクトを上書きしないため）。

すでに自分の `.clasp.json` があるフォルダでは `clasp create` は不要です。コードを直したあとは `clasp push` だけで更新できます。

`Exception: 引数が大きすぎます: key` と出る場合は、フォントや背景画像をファイルに埋め込んだ古い版のことがあります。このリポジトリの最新を `git pull` してから、もう一度 `clasp push` してください。

### 3. Google Calendar API を有効にする

Apps Script エディタ（`clasp open`）で **サービス → Google Calendar API** を追加します。`appsscript.json` に書いてあれば、push した時点で付いていることもあります。

Meet 付きの予定作成、空き時間の判定、管理画面のカレンダー表示名（左の一覧で付けた別名）に使います。

### 4. 初回セットアップ（管理キーとデータシート）

エディタから関数 `setupSlotly` を実行します。初回はカレンダー・スプレッドシート・メール送信の権限確認が出ます。許可してください。

実行ログに次が出ます。

- **管理キー**（管理画面の合言葉。他人に見せない）
- **予約データ** スプレッドシートの URL（内部ログ。名前は「Slotly 予約データ」）
- 管理画面の開き方: `(デプロイURL)?page=admin&key=管理キー`

`setupSlotly` を再度実行しても、既存の管理キーとシートは使い回します。キーは変わりません。

### 5. ウェブアプリとしてデプロイする

エディタで **デプロイ → 新しいデプロイ → 種類: ウェブアプリ**。

| 項目 | 値 |
| --- | --- |
| 実行するユーザー | **自分** |
| アクセスできるユーザー | **全員（匿名を含む）** |

表示された URL が予約ページです。ゲストはログイン不要です。アプリはホストの権限でカレンダーに予定を書き、ゲストへメールを送ります。

コードを直したあとは **デプロイ → デプロイを管理 → 編集 → 新しいバージョン** で、同じ URL のまま更新します。

### 6. 管理画面で最初の設定をする

```
(予約ページのURL)?page=admin&key=管理キー
```

最低限、次を確認して **設定を保存** します。保存に成功すると、右上に「保存しました」と出ます。

- **表示名** … 予約ページの見出し（空なら「空き時間から予約する」）
- **許可するメールドメイン** … 予約できるメールのドメイン。空なら制限なし。1行に1つ、`@` は不要（例: `example.com`）
- **タイムゾーン** … 空き枠と時刻表示（初期値 `Asia/Tokyo`）
- **受付時間** … 曜日ごとの時間帯。オフにした曜日は休み。1日に複数の帯を足せる。他の曜日へ複製もできる
- **会議前後のバッファ（分）** … 既存予定の前後を空けます（初期値 15）
- **最短何分前まで予約可** … 直前枠を閉めます（初期値 120）
- **何日先まで予約可** … 公開する先の日数（初期値 28、最大 90）
- **予定の書き込み先** … 確定予約を入れるカレンダー（1つ）
- **空き判定に使うカレンダー** … 予定が入っている時間を空きから除外（1つ以上、複数可）

初期の受付時間は **月〜金 10:00–18:00**、土日は休みです。書き込み先・空き判定はどちらもメインカレンダーです。

カレンダーの名前は、Google カレンダー左の一覧と同じです。別名を付けていればそれを、なければ本体の名前を出します。並びもその表示名順です。メインカレンダーには「（メイン）」、自分のものでないカレンダーには「（共有）」が付きます。

「書き込み先」と「空き判定」は分けられます。例: 予定は専用の「予約」カレンダーに書き、空き判定にはメイン＋仕事用を見る。祝日カレンダーを空き判定に入れると、祝日は全部塞がります。

## 使い方

導入（クローン → デプロイ → 管理画面で保存）が終わっている前提です。

### ゲスト（予約する側）

1. ホストから渡された予約ページを開く
2. **所要時間** と **Google Meet / Meetなし** を選ぶ
3. 空きのある日から時刻を選ぶ（点が付いている日）
4. **お名前** と **メールアドレス** を入れる（予定のタイトル・説明は任意）
5. 予約を確定する

許可ドメインを設定している場合、その `@ドメイン` のメールだけ予約できます。ページ下部に、URL を予約する相手以外へ共有しない旨が出ます。

確定すると、次が起きます。

- ホストの「書き込み先」カレンダーに予定が入る（ゲストが招待される）
- ゲストに確認メールが届く（Meet の URL、ICS、キャンセルリンク）。Google カレンダーには招待メールが別途届く
- 確定画面でも ICS ダウンロードとキャンセルができる

予定のタイトルを空にすると、カレンダー上の件名は「（表示名） / （ゲスト名） さん（Slotly）」になります。Meet 付きのときは、場所が `Google Meet (URL)` と出ます。

キャンセルは `?page=cancel&token=…` のリンクからです。確定中の予約を取り消すと、カレンダー上の予定も削除され、ゲストにキャンセルメールが送られます。キャンセル済みの画面から、同じ予約ページで新しく予約し直せます。

### ホスト（管理する側）

日常の操作はカレンダーそのものです。予約が入ると、選んだカレンダーに予定が増えます。予定の説明にキャンセル URL は入らないので、ゲストへのキャンセル案内はメールと確定画面側です。

設定を変えるときは管理画面（`?page=admin&key=…`）だけを使います。受付時間を変えたり、空き判定に別カレンダーを足したりできます。

管理キーを忘れたときは、Apps Script エディタで `setupSlotly` を再実行し、ログの管理キーを見てください。

## 複数の予約表を作りたい場合

**1つの GAS デプロイ = 1つの予約ページ** です。1つのデプロイの中に、用途別の「イベントタイプ」を並べる機能はありません。

同じページ上でゲストが所要時間（15〜240分）と Meet の有無を選ぶことはできます。それは複数の予約表ではなく、**1枚の表のオプション** です。

別の受付時間・別の書き込み先カレンダー・別の表示名が欲しいときは、**Apps Script プロジェクトをもう1つ作り、別デプロイ** してください。それぞれに管理キー・設定・「Slotly 予約データ」シート・予約 URL が付きます。

やり方の例:

1. リポジトリをもう一度クローンする（別フォルダにする）

```bash
git clone https://github.com/NameOfSummer/slotly.git slotly-別用途
cd slotly-別用途
```

エディタで既存プロジェクトの「コピーを作成」でも構いません。その場合はコピー側の `.clasp.json` を使います。

2. コピー側では、元の `.clasp.json` を使わず `clasp create --type standalone --title Slotly（用途名）` で別プロジェクトにする
3. `clasp push` → `setupSlotly` → ウェブアプリを新たにデプロイ
4. 管理画面で、その表用の受付時間とカレンダーを設定する

ゲストには用途ごとの URL を渡します。同じ Google アカウントで複数デプロイして問題ありません。設定はプロジェクトごとに独立しています。

## 予約表を閉鎖したい時

アプリ内に「公開停止」「このページを閉じる」ボタンはありません。次のいずれかです。

### 当面、新規予約だけ止めたい（ページは残す）

管理画面で **すべての曜日の受付時間をオフ（休み）** にして保存します。予約ページは開けますが空き枠は出ません。すでに入っている予定はそのままです。ゲストのキャンセルリンクも、ウェブアプリが生きていれば使えます。

これが、このアプリの設定だけでできる止め方です。

### URL 自体を止めたい（推奨）

Apps Script エディタで **デプロイ → デプロイを管理** を開き、ウェブアプリのデプロイを **アーカイブ**（または削除）します。予約 URL は応答しなくなります。これが実質的なオフラインです。

注意: アーカイブすると、ゲストの **キャンセルリンクも使えなくなります**。残っている予定はホストがカレンダーから削除してください。

### 自分以外は開けなくする

デプロイの「アクセスできるユーザー」を **自分のみ** に変える方法もあります。ゲストは予約できません。ホストはログインした状態なら管理画面を開けることがあります。完全に URL を無効にしたいなら、アーカイブの方がはっきりします。

閉じたあとも、カレンダーに残った予定・すでに送ったメール・スプレッドシートの予約行は消えません。

## このアプリの使用をやめる（削除）

Slotly をアンインストールする専用画面はありません。Google 上の部品を、使うのをやめる順に外します。

1. **残っている予約を片づける**  
   今後の予定はカレンダーから削除するか、ゲストに連絡する。ウェブアプリを消すとキャンセルリンクは死にます。
2. **ウェブアプリのデプロイをアーカイブ / 削除する**  
   予約 URL を止める。
3. **Apps Script プロジェクトを削除する**  
   [script.google.com](https://script.google.com) から当該プロジェクトを削除。管理キーや設定（スクリプトのプロパティ）も一緒に消えます。
4. **スプレッドシート「Slotly 予約データ」を削除する**（不要なら）  
   `setupSlotly` が Google ドライブに作った内部ログです。プロジェクトを消してもシートは自動では消えません。
5. **カレンダー予定**（残したいもの以外）  
   Slotly が作った予定は、プロジェクト削除では消えません。タイトルはだいたい「（表示名） / （ゲスト名） さん（Slotly）」です（ゲストが予定のタイトルを入れた場合はそちら）。必要なものだけ手で消してください。
6. **権限（OAuth）**  
   スクリプトを削除すれば、そのプロジェクトへの許可は不要になります。残っている場合は、Google アカウントの「サードパーティ製のアプリとサービス」などから、当該スクリプトへのアクセスを解除します。

**自動では消えないもの**

- すでにカレンダーに入っている予定（ホスト側も、ゲストが追加したコピーも）
- すでに送った確認メール・キャンセルメール（相手の受信箱）
- ゲストがダウンロードした ICS
- 「Slotly 予約データ」スプレッドシート（手順 4 で消さない限り）

コードやローカルのクローンを消すだけでは、公開中のウェブアプリは止まりません。必ずデプロイのアーカイブと、不要ならスクリプトプロジェクトの削除まで行ってください。

## 開発者向け

クローンしたフォルダで、GAS に上げる前に UI だけ見る場合:

```bash
git clone https://github.com/NameOfSummer/slotly.git
cd slotly
node tools/preview.mjs
```

http://127.0.0.1:3456 が予約画面、`?page=admin` が管理画面です。カレンダー連携はモックです（保存トーストや使い方は本番と同じ UI で確認できます）。
